# Runtime API, SDK & API Keys

The Atai Runtime is the single, unified API surface behind every business Atai builds. The same Runtime powers the AI teams, payments, maps, messaging, auth, search and data features you use inside the product — and you can call it directly from your own code with one key. This guide explains what the Runtime is, how to install the SDK, where to create and rotate keys, every endpoint, security rules, and fixes for the common problems.

> Short version: install `@atai-group/sdk`, set `ATAI_API_KEY`, and call `atai.ai.chat(...)` / `atai.payments.*` / etc. The base URL is `https://atai.ink/api/runtime/v1`. Everything below is the long, link‑by‑link version.

## 1. What the Atai Runtime is

The Runtime is **supporting infrastructure inside the product you build**, not the product itself. Instead of stitching together many vendors (an LLM provider, a payments processor, a maps API, an SMS gateway, an auth service…), you get one key that reaches all of them through one normalized API.

The capabilities exposed through the Runtime are:

| Capability | What it does |
|---|---|
| `ai` | Chat, completions, and other model calls |
| `payments` | Charges, payouts, subscriptions, refunds |
| `maps` | Geocoding, places, routing |
| `messaging` | Email and SMS send |
| `auth` | Token / session verification helpers |
| `search` | Indexed search over your data |
| `data` | Structured reads/writes against your project data |

You normally never configure provider names, keys, or wire formats — the Runtime owns that. Provider neutrality is a design guarantee: nothing provider‑specific crosses the Runtime boundary.

## 2. The Atai SDK (`@atai-group/sdk`)

The official typed client is `@atai-group/sdk`. It gives you typed input/output, client‑side validation, normalized errors, and request cancellation.

**Install**

```bash
npm install @atai-group/sdk
# or
pnpm add @atai-group/sdk
```

**Initialize**

```ts
import { Atai } from "@atai-group/sdk"

const atai = new Atai({
  apiKey: process.env.ATAI_API_KEY!,   // atai_<environment>_<secret>
  // baseUrl is optional — defaults to Atai's production runtime origin.
})
```

**Your first AI call**

```ts
const result = await atai.ai.chat({
  messages: [
    { role: "system", content: "You are a helpful assistant." },
    { role: "user", content: "Write a haiku about databases." },
  ],
  temperature: 0.7,
})
console.log(result.content)
```

**Thin server proxy (recommended shape)**

```ts
// app/api/chat/route.ts (server) — the key never leaves the server
import { Atai } from "@atai-group/sdk"

const atai = new Atai({ apiKey: process.env.ATAI_API_KEY! })

export async function POST(req: Request) {
  const { message } = await req.json()
  const result = await atai.ai.chat({
    messages: [{ role: "user", content: message }],
    max_tokens: 500,
  })
  return Response.json({ reply: result.content })
}
```

If your application was **generated by Atai**, the runtime credential is delivered to you automatically — no dashboard step. At build completion Atai creates a project‑scoped key with least‑privilege scopes, injects it into your app's secret store as `ATAI_API_KEY`, and discards the plaintext (it is never persisted in plaintext, logged, or returned again).

## 3. API keys: where to create and rotate them

There are two places to manage keys, depending on scope:

| Where | URL | Use it for |
|---|---|---|
| Project runtime keys | [https://atai.ink/project/PROJECT_ID/runtime/keys](https://atai.ink/project/PROJECT_ID/runtime/keys) | Keys scoped to one project (recommended for apps you deploy) |
| Developer keys | [https://atai.ink/developers/keys](https://atai.ink/developers/keys) | Account‑level keys for experimenting and the playground |

**Key format**

Keys look like `atai_<environment>_<secret>` (e.g. `atai_proj_...`). The secret half is shown **once** at creation and is never retrievable again. Atai stores only a SHA‑256 hash; the plaintext is discarded.

**Create a project key**

1. Open [https://atai.ink/project/PROJECT_ID/runtime/keys](https://atai.ink/project/PROJECT_ID/runtime/keys).
2. Click **Create key**, give it a name and a scope (e.g. only `email` for a worker that only sends mail).
3. Copy the full key immediately — you will not see it again.
4. Store it in your environment / secret manager as `ATAI_API_KEY`.

**Rotate a key**

- In the UI: open the key and click **Rotate** (atomic — the old secret dies the moment the new one is issued).
- Via API: `POST /api/runtime/keys/[keyId]/rotate` (see endpoint list).
- Rotate on a schedule, and rotate immediately if you suspect leakage.

**Development vs production keys**

Use a **development** key while building and a **production** key in live deployments. Different keys mean isolated usage and isolated limits, so a bug in dev can't blow your production quota.

## 4. Base URL, authentication & the raw REST API

- **Base URL:** `https://atai.ink/api/runtime/v1`
- **Auth:** `Authorization: Bearer $ATAI_API_KEY`
- **Request body:** `{ "capability": "...", "operation": "...", "input": { ... } }`

**List capabilities**

```bash
curl https://atai.ink/api/runtime/v1
```

**Call a capability**

```bash
curl -X POST https://atai.ink/api/runtime/v1 \
  -H "Authorization: Bearer $ATAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "capability": "ai", "operation": "chat", "input": { "messages": [{ "role": "user", "content": "Hello" }] } }'
```

**Health check (requires a key)**

```bash
curl https://atai.ink/api/runtime/v1/health \
  -H "Authorization: Bearer $ATAI_API_KEY"
```

The REST surface is fully documented and works from any language — the SDK exists for typed input/output, validation, normalized errors, and cancellation. If you prefer no SDK, `POST /api/runtime/v1` with a Bearer key and a `{ capability, operation, input }` body is all you need.

## 6. Security & environment hygiene

- **The key never leaves the server.** Store keys in environment variables or your platform's secret manager — never in source, never in `localStorage` or cookies. The SDK itself never writes your key anywhere.
- **Identity is server‑derived.** `userId` / `projectId` / `environment` come exclusively from the key record; client‑supplied identity fields are structurally rejected.
- **Keys are hashed at rest.** Atai stores only a SHA‑256 hash; plaintext is shown once at creation and never retrievable.
- **Scope narrowly.** If a worker only sends email, give it `["email"]`, not every capability.
- **Rotate on a schedule**, and immediately on suspicion of leakage. Rotation is atomic.
- **One‑way traffic.** The SDK sends nothing anywhere except your requests to the Atai origin. No telemetry, no per‑request base‑URL overrides, no storage.

## 8. Common problems

### "Unauthorized" / 401 when calling the Runtime
- *Cause:* missing or malformed `Authorization: Bearer` header, or a revoked/expired key.
- *Fix:* confirm `ATAI_API_KEY` is set in the environment where the code runs (not just your local shell), the header is exactly `Authorization: Bearer <key>`, and the key still exists at [https://atai.ink/developers/keys](https://atai.ink/developers/keys) or [https://atai.ink/project/PROJECT_ID/runtime/keys](https://atai.ink/project/PROJECT_ID/runtime/keys). Rotate if unsure.

### Key works locally but not in deployment
- *Cause:* the environment where the app runs doesn't have `ATAI_API_KEY` (e.g. a forgotten secret in the host's dashboard), or a dev key is used in production where the project scope differs.
- *Fix:* add the variable in the deployment's secret store, and use a **production** key for live deployments. Verify with `GET /api/runtime/v1/health`.

### "Invalid capability" / "unknown operation"
- *Cause:* `capability` or `operation` string doesn't match what the Runtime exposes.
- *Fix:* call `GET /api/runtime/v1` to list the exact capability/operation names, and check spelling/case. The SDK throws a normalized error with a code such as `atai_invalid_config` for malformed input.

### Rate limited / 429
- *Cause:* you exceeded the key's request or token limit.
- *Fix:* check [https://atai.ink/project/PROJECT_ID/runtime/limits](https://atai.ink/project/PROJECT_ID/runtime/limits); back off and retry with exponential delay; if you need a higher ceiling, review your plan at [https://atai.ink/pricing](https://atai.ink/pricing).

### Cannot find where to create a key
- *Cause:* looking on the wrong page.
- *Fix:* project keys live at [https://atai.ink/project/PROJECT_ID/runtime/keys](https://atai.ink/project/PROJECT_ID/runtime/keys); account keys at [https://atai.ink/developers/keys](https://atai.ink/developers/keys). Replace `PROJECT_ID` with your real project id.

### SDK throws "Malformed configuration"
- *Cause:* bad `baseUrl` or missing `apiKey`.
- *Fix:* omit `baseUrl` (it defaults to production) and ensure `apiKey` is a non‑empty string from `process.env.ATAI_API_KEY`. Error code is `atai_invalid_config`.
